Notes:
- The draft model roughly triples decode speed at 4 tokens (TP1 code 6.8 → 24.2 tok/s).
- TP2 is about 1.7× TP1 at every setting. The model is dense, so decode is limited by memory bandwidth, and two
  Sparks each read half the weights.
- Code keeps gaining up to 6 draft tokens because code is predictable: the 5th and 6th draft positions are still
  accepted 54–75% of the time. Prose and the long prompt stop improving at about 4, and runs at 5–6 vary more
  (TP1 code 26.2–29.6 tok/s across the three runs at 6). 4 is the default; `DRAFT_TOKENS=6` suits single-user coding.
- Deeper drafting does more work on rejected tokens, which costs aggregate throughput when several requests share
  the server. This suite measures single-stream speed only.
- Cold prefill is the same with or without the draft model (TP1 ~1,400 tok/s, TP2 ~1,750–1,990 tok/s at ~6.7K).
